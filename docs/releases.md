# All-platform builds and publishing

The public browser distribution runs without the Node backend or API credentials.
It uses the bundled demo catalog and public test media, and displays a demo notice.
The same release also carries native development packages, described below.
Browser ZIPs are not TV installers; see [TV installation](tizen.md).

## Download and run

Download `streamed-web-vVERSION.zip` and `SHA256SUMS` from
[GitHub Releases](https://github.com/abhishekbindlish1/Streamed/releases).
`v1.0.0` is the original browser-only release. All-platform downloads start with
`v1.1.0-preview.3`. Preview tags are published as prereleases.
Keep both files in the same folder and verify the ZIP before extraction:

```sh
sha256sum --check --ignore-missing SHA256SUMS
unzip streamed-web-v1.1.0-preview.3.zip -d streamed-web
cd streamed-web
python3 -m http.server 8080
```

Open `http://localhost:8080`, select a profile, then choose a sport. Use HTTP
rather than opening `index.html` as a file. Browsing the catalog needs no backend;
HLS.js and video playback need Internet access. Browser-local profiles stay on
that browser/origin. No npm installation is needed to consume a release ZIP.

To use your own authorized match backend, edit the extracted
`data/config.local.js`, set `DEMO_MODE` to `false`, and set
`INTERNAL_API_BASE_URL` to its HTTPS origin. Never put credentials in that file.
The ZIP and hosted demo do not include the optional Node Team Hub backend.

## Build locally

Use Node.js 24 LTS and the `zip` command (preinstalled on the hosted Ubuntu runner):

```sh
npm run build
```

This creates `apps/web/dist/site/` for static hosting and `apps/web/dist/releases/` containing the
versioned ZIP and SHA-256 checksum. `BUILD.json` records the version, source commit,
and demo mode. The build copies an explicit frontend allowlist and generates clean
public configuration, so local settings, environment files, server code, caches,
test dependencies, and certificates are excluded. A regular source build is
unaffected by the generated demo settings. The generated distribution also works
under a subpath, such as `/Streamed/`; CI exercises that exact layout.

## Publish a version

1. Update `version` in `apps/web/package.json` and the root `package-lock.json` together, and commit
   the change. For a preview, use a version such as `1.1.0-preview.3`.
2. Push the commit, then create and push its matching tag:

   ```sh
   git tag v1.1.0-preview.3
   git push origin v1.1.0-preview.3
   ```

3. GitHub Actions runs all tests, checks that the tag matches the package version,
   and builds/tests the native apps and both backend services through a reusable
   workflow. The exact release IPK and TPK must also pass the actual LG Simulator
   and Samsung emulator jobs. Only after every required check passes does it publish the browser
   ZIP, native TPK/APKs, SHA256SUMS, BUILD-INFO.json, and INSTALL.md to one release. If validation
   fails, no release is published. Rerunning a successful tag workflow replaces
   its generated assets; it does not move the tag.

Every successful push/PR also retains the browser ZIP as a workflow artifact for
14 days. These artifacts are useful for testing; Releases provide the stable
download location for consumers. Do not move published tags; use a new version
for changed code. Repository source-code ZIPs generated by GitHub are distinct
from the ready-to-serve `streamed-web-*.zip` release asset.

## Host the demo on GitHub Pages

In repository **Settings → Pages → Build and deployment → Source**, choose
**GitHub Actions**. This is a one-time repository setting requiring appropriate
repository access. Pages must be available for the repository's visibility/plan.
Then rerun the failed `pages` job, or run the CI workflow manually on `main`.

After tests pass on `main` and Pages is enabled, the Pages job deploys the tested
`apps/web/dist/site/` artifact. The deployment job is skipped while the repository
has no Pages site; this does not skip application tests.
Pull requests and tags never deploy the demo. The expected project URL, once
deployment succeeds, is `https://abhishekbindlish1.github.io/Streamed/`; the Pages
job reports the actual deployment URL. A custom domain or repository settings
can change it. A Pages setup failure does not prevent a separate tag release.

Pages hosts static frontend files; it cannot run `server.js`, store server-side
credentials, or provide the optional AI standings endpoints. Keep those on a
separately secured backend if you enable them later.

## Native downloads

Samsung signing runs once per build, rather than once per download. See
[Samsung distribution](samsung-distribution.md) for automatic signing with a
stable profile, development device authorization, and the inspected working TPK.
For an LG TV's built-in webOS, download the **IPK**, not either Android APK, and
follow [LG installation](lg-installation.md).

| Asset | Intended use |
| --- | --- |
| `streamed-tizen9-1.13.34-development.tpk` | Tizen 9 .NET development build; current SDK development signing, not universal Samsung TV installation. |
| `streamed-android-arm-development-vVERSION.apk` | Experimental ARM32 and ARM64 Android systems, API 26+; one debug-signed APK with the real pairing/login flow. |
| `streamed-android-emulator-sandbox-vVERSION.apk` | x86 and x64 Android emulators with the local fixture server; no real account sign-in. |
| `streamed-webos-development-vVERSION.ipk` | LG webOS TV preview with an offline catalog and owned sample media; install using LG Developer Mode. |

`BUILD-INFO.json` records the exact source commit and platform/signing constraints.
The release assembler rejects missing platforms, mismatched commits, dirty native
builds, or altered package checksums. `SHA256SUMS` covers the packages and install
notes. CI verifies both APK signatures before publishing.
The Android collector also requires both device ABIs (`armeabi-v7a` and
`arm64-v8a`), both emulator ABIs (`x86` and `x86_64`), and a compatible minimum OS
in the actual APK metadata. Older ARM64-only downloads can fail on TVs with a
32-bit Android OS. See [Android installation](android-installation.md).
The TPK collector checks every embedded author/distributor certificate's validity
and records the earliest expiry as `signingExpires`. Tizen Studio's developer CA
currently expires January 1, 2027. By default the build generates a disposable
author outside the checkout, so uninstall an older build when its signing identity
changes. Configured Samsung profiles can provide a stable identity.
Earlier preview TPKs used expired NuGet SDK defaults; rebuild with
`scripts/build-tizen-development.py` and an authorized profile. Preview.6 is not
published while Samsung runtime validation remains blocked.
The LG collector also inspects the IPK's embedded manifest and build metadata;
an old package from another source commit cannot be published as the new build.

Samsung TV installation requires a compatible OS and an authorized author and
distributor signing profile. The native TPK targets API 9 and cannot run on the
2020 Tizen 5.5 TV; that model uses the web client. Consumer-quality TV signing,
production Android signing/update identity, login, and media acceptance testing
remain separate from these development downloads. Do not publish private keys or
passwords; signing profiles must be supplied securely when that integration is
configured. The Android debug signer is not stable across independent runner
builds, so installing a later development APK may require uninstalling first.

The source repository is currently private. Releases and downloads are available
to people with repository access; this setup does not change source visibility.
Native packages are also retained as normal workflow artifacts for branch builds.
